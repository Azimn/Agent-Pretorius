1 Overview & Design Philosophy
SoulCore Framework (SCF) is a deterministic character engine for games and interactive 
systems. It is designed to make NPCs and digital companions feel genuinely coherent over time
— not through prompt tricks, but through real inner state, persistent memory, and a 
mathematically enforced voice.
1.1 Core Goals
• Character Cohesion — Voice Gate + axioms + forbidden patterns prevent drift. A 
character running SCF cannot become a different person no matter how the 
conversation goes.
• Lightweight Tier 0 — Pure Python stdlib, < 50 MB RAM idle. Runs on a Raspberry Pi or 
inside a game with 500 simultaneous NPCs. No torch, no llama.cpp at this tier.
• True Persistence — .snp files + SessionSnapshot survive device changes, restarts, and 
years. Export on a laptop, import on a phone, continue identically.
• Distillation Loop — Higher-tier AI observations become permanent Tier 0 wisdom. The 
engine learns from every frontier-model conversation without needing the frontier model 
to be present.
• Testability — Automated consistency metrics: prompt-to-line, line-to-line, value drift 
detection. "Feels genuine" must be provable.
1.2 What Makes SCF Different
Most NPC AI either (a) calls an LLM on every turn and hopes it stays consistent, or (b) uses 
rigid scripts with no personality. SCF does neither. The Tier 0 state machine is the character's 
permanent identity. Higher tiers are amplifiers that augment it — they can be removed entirely 
and the character still functions. The .snp file is a cartridge; the storage backend is the save file.
Key Architectural Insight
SCF separates WHAT the character is (persona .snp file — immutable, shareable) from WHAT the 
character remembers (storage backend — mutable, session-scoped). This is the same design as a 
game console: the disc is the soul, the memory card is the experience.
1.3 Tier Architecture
SCF operates across four tiers. Each tier gracefully degrades to the one below it.

3 Module Design Reference
3.1 scf/tier_interface.py
Defines the Proposal dataclass and TierInterface ABC. The Proposal is the single structured 
object that crosses the tier boundary. Key invariant: emotional_adjustments are DELTA values, 
not absolute values. Every amplifier must implement amplify() and is_available().
3.2 scf/storage.py
Abstract StorageBackend. Three domain tables: emotional_state (variable_name → int), 
key_memories (episodic records, max 512 chars each), learned_directives (trigger/action pairs).
Two concrete implementations: SQLiteBackend (production) and BTreeBackend 
(embedded/shelve).
3.3 scf/session.py
SessionSnapshot dataclass + checksum logic. The checksum covers entity_name, variables, 
and last_updated only — minimal set for identity and tamper detection. Checksum formula is 
fixed by spec and must not change between versions:
hashlib.sha256(
 json.dumps({
 'variables': snap.variables,
 'last_updated': snap.last_updated,
 'entity_name': snap.entity_name
 }, sort_keys=True).encode()
).hexdigest()
3.4 scf/engine.py (SoulCoreEngine)
The orchestration layer. Manages the full pipeline per turn: amplifier selection → Voice Gate → 
distillation → Tier 0 fallback → memory persistence.
Voice Gate — four steps in strict order:
1. Confidence check: proposal.confidence >= voice.confidence_threshold
2. Forbidden lexicon: whole-word case-insensitive regex against voice.forbidden_lexicon
3. Axiom guard: patterns from constraints.hard_colliders
4. Accept
Critical Spec Rule
Distillation (new_directives, new_knowledge, emotional_adjustments) runs unconditionally on every

"""Tier interface contracts for the SoulCore Framework.

higher-tier amplifier back to Tier 0) and the TierInterface abstract base

import abc

@dataclass
class Proposal:
 """Communication envelope from a higher-tier amplifier to Tier 0.
 Fields
 ------
 response_text : Optional[str]
 The amplifier's proposed verbatim response text. ``None`` means the
 amplifier declines to suggest a response (Tier 0 generates its own).
 confidence : float
 Amplifier's self-reported confidence in *response_text*, in [0.0, 1.0].
 The Voice Gate rejects proposals below the persona's threshold.
 new_directives : List[Dict[str, Any]]
 Behavioural rules to distil into Tier 0. Each entry must have at
 minimum "trigger" (str) and "action" (str).
 new_knowledge : List[Dict[str, Any]]
 Declarative facts to persist. Each entry must have at minimum
 "summary" (str) and "tags" (List[str]).
 emotional_adjustments : Dict[str, int]
 **DELTA values, not absolute values.** Each key is a state-variable
 name; each value is the signed integer amount to ADD to the current
 value. Tier 0 clamps the result to the variable's [min, max] range.
 Example: {"hubris": +5, "affection": -3}
 tier_used : str
 Human-readable identifier of the producing tier.
 trace : Dict[str, Any]
 Arbitrary debug / audit metadata. Never affects behaviour.
 """
 response_text: Optional[str] = None
 confidence: float = 1.0
 new_directives: List[Dict[str, Any]] = field(default_factory=list)

 emotional_adjustments: Dict[str, int] = field(default_factory=dict)
 tier_used: str = "unknown"

5 Key Invariants & Implementation Notes
5.1 Invariants That Must Never Be Broken
• emotional_adjustments are DELTA values. Never absolute. Applying them absolute 
silently corrupts state.
• Distillation runs on every non-None Proposal, regardless of Voice Gate outcome.
• The Voice Gate always runs four steps in order. Skipping step 3 (axiom guards) is a 
security hole.
• The session checksum formula is fixed. It must not change between versions — old 
snapshots must always validate.
• Dialog summaries are capped at 480 chars in engine.py (hard limit is 512 at the storage 
layer).
• Tier 0 fallback must stay in character. No meta responses like 'offline mode'.
• No eval() or exec() anywhere in the codebase. The DSL parser (Phase 2) uses recursive
descent.
